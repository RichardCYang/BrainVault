# HTTPS reverse-proxy deployment

BrainVault continues to listen on private HTTP while Caddy, Synology Reverse Proxy, NGINX, or Nginx Proxy Manager terminates public TLS. The application trusts `X-Forwarded-Proto` only when the connecting proxy matches the configured trust rule.

## BrainVault environment

A same-host proxy should normally keep BrainVault bound to loopback:

```env
NODE_ENV=production
HOST="127.0.0.1"
PORT=4000

PUBLIC_ORIGIN="https://notes.example.com"
WEBAUTHN_RP_ID="notes.example.com"
WEBAUTHN_ORIGIN="https://notes.example.com"
CORS_ORIGIN="https://notes.example.com"

HTTPS_MODE=proxy
HTTPS_REDIRECT=true
HTTPS_HEALTHCHECK_BYPASS=true
TRUST_PROXY_ADDRESSES="loopback"
TRUST_PROXY_HOPS=0
```

For a proxy in another container or host, replace `loopback` with the exact proxy IP or the narrowest practical CIDR and bind `HOST` only to the private interface reachable by that proxy. `TRUST_PROXY_HOPS=1` remains available for a topology that always has exactly one proxy hop, but explicit addresses are safer when the backend port could otherwise be reached directly. Never configure both trust options.

`HTTPS_MODE=proxy` requires a trusted proxy rule. Requests recognized as HTTPS continue normally. Plain HTTP requests are redirected with status 308 to `PUBLIC_ORIGIN`; set `HTTPS_REDIRECT=false` to return `426 HTTPS_REQUIRED` instead. `/health` remains available on the private HTTP listener by default for local checks.

## Caddy

Copy `Caddyfile.example`, change the domain/backend, and reload Caddy. A basic `reverse_proxy` forwards the original protocol and supports WebSocket upgrades automatically.

## NGINX

Copy the `map` and server blocks from `nginx.conf.example`, update the certificate paths, test with `nginx -t`, then reload. The WebSocket `Upgrade` and `Connection` headers are needed for `/api/collaboration/`.

## Nginx Proxy Manager

Create a Proxy Host with:

- Domain: `notes.example.com`
- Scheme: `http`
- Forward host/IP: the BrainVault private address
- Forward port: `4000`
- Websockets Support: enabled
- SSL certificate: selected
- Force SSL: enabled

Nginx Proxy Manager normally supplies the forwarded host/protocol headers. Do not expose port 4000 publicly; allow only the proxy network.

## Synology DSM Reverse Proxy

In **Control Panel → Login Portal → Advanced → Reverse Proxy**, create:

- Source protocol: `HTTPS`
- Source hostname: `notes.example.com`
- Source port: `443`
- Destination protocol: `HTTP`
- Destination hostname: `127.0.0.1` or the BrainVault private address
- Destination port: `4000`

Under **Custom Header**, choose **Create → WebSocket** so collaboration upgrades are forwarded. Also add `X-Forwarded-Proto` with value `$scheme` when it is not already generated by your DSM version; BrainVault intentionally requires the trusted proxy to report `https`. Attach the certificate for `notes.example.com` in DSM and optionally add a separate HTTP source rule that redirects to HTTPS. Keep the BrainVault destination port private.

## Verification

After startup, the server log should show `HTTPS reverse-proxy mode enabled`. Verify:

```bash
curl -I http://127.0.0.1:4000/health
curl -I -H 'Host: notes.example.com' http://127.0.0.1:4000/
curl -I -H 'X-Forwarded-Proto: https' http://127.0.0.1:4000/
curl -I https://notes.example.com/
```

The private health check should return 200. A private non-health HTTP request should return 308 (unless redirecting is disabled), the trusted forwarded-HTTPS simulation should return 200, and the public URL should return the application without a redirect loop. Open two browser windows on the same shared page to confirm WebSocket collaboration.
