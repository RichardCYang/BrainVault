# はじめに

## 要件

- Node.js 22.x系では22.23.2以降、Node.js 24.x系では24.18.1以降、またはNode.js 26.5.1以降
- npm 10.9以降
- 稼働中のMariaDBサーバー

Dockerは必須ではありません。`DATABASE_URL`の認証情報で接続できる限り、MariaDBはローカルまたはリモートホストで実行できます。本番環境ではリモートデータベースURLに`?ssl=true`を追加する必要があり、BrainVaultは平文のリモートデータベース通信を拒否します。

## 初回セットアップ

データベース認証情報を対話形式で設定してから、依存関係をインストールします。

```bash
npm run db:configure
npm install
```

`db:configure`はNode.jsの組み込み機能のみを使用するため、`npm install`より前に実行できます。データベースのユーザー名とパスワードを入力し、対話型ターミナルではパスワードを非表示にしたまま`.env`内の`DATABASE_URL`を更新します。現在のプロトコル、ホスト、ポート、データベース名は維持されます。`.env`が存在しない場合は、認証情報を適用する前に`.env.example`から作成します。

代わりに、ランダムなデータベース・JWT・MFAシークレットを含むローカル環境ファイルを作成するには、次を実行します。

```bash
npm run env:init
```

実際の`.env`ファイルは絶対にコミットしないでください。リポジトリでは無視されます。共有可能なデフォルト値は[`.env.example`](../../../.env.example)に保持してください。

## 開発サーバーの起動

```bash
npm run dev
```

`AUTO_BOOTSTRAP_DATABASE=true`の場合、起動時に許可されていればデータベースを作成し、ベースラインスキーマを調整したうえで、ページ権限と永続Yjs更新用の`020_page_sharing_yjs_collaboration.sql`を含む未適用のマイグレーションを実行します。MariaDBの準備が完了しHTTPサーバーが待ち受け状態になると、開発コマンドはアプリをプライベート／シークレットブラウザーウィンドウで1回開きます。

アプリは次のURLで利用できます。

```text
http://localhost:4000
```

プライベートモードでの起動はChrome、Edge、Firefox、Braveに対応しています。BrainVaultはまずシステムの既定ブラウザーにプライベートウィンドウを要求し、その後、インストール済みの対応ブラウザーに各ブラウザー固有のプライベートモード用コマンドラインスイッチを指定して再試行します。プライベートウィンドウを起動できない場合は問題を報告し、通常のブラウザーウィンドウを意図的に開きません。Safariはコマンドラインから直接プライベートモードで起動できないため、macOSで自動起動を使用するには対応する別ブラウザーがインストールされている必要があります。

## 任意: デモデータ

デモのシードは既定で無効化されており、リポジトリで定義されたパスワードを使用することはありません。サンプルワークスペースを作成するには、UTF-8で72バイト以下、かつ12～128文字の明示的なパスワードを指定してください。

```bash
BRAINVAULT_SEED_DEMO=true \
BRAINVAULT_DEMO_USERNAME=demo \
BRAINVAULT_DEMO_PASSWORD="use-a-unique-local-password" \
npm run db:seed
```

実際のアカウントパスワードを再利用しないでください。シードコマンドはユーザー名を表示しますが、平文パスワードをデータベースのハッシュ以外に表示または保存することはありません。

## データベースのブートストラップ

最も単純な構成では、`DATABASE_URL`のアカウントに対象データベースの作成権限とDDL文の実行権限が必要です。

そのアカウントがまだ存在しない場合は、管理者接続を追加します。

```env
MARIADB_ADMIN_URL="mariadb://root:your-root-password@127.0.0.1:3306"
```

これにより、ブートストラップ処理は次の操作を実行できます。

1. データベースが存在しない場合に作成します。
2. `DB_USER_HOSTS`に指定された各正確なホストに対してアプリケーションユーザーを作成または更新します。
3. 同じユーザー名の従来のワイルドカードホストアカウントを削除します。
4. 対象データベースに必要なアプリケーション権限とマイグレーション権限のみを付与します。
5. ベースラインスキーマを調整します。
6. まだ実行されていないマイグレーションを適用します。

アプリケーション外でスキーマ変更を管理する場合は、起動時ブートストラップを無効にします。

```env
AUTO_BOOTSTRAP_DATABASE=false
```

データベースタスクは個別にも利用できます。

```bash
npm run db:init
npm run db:migrate
npm run db:seed
```

初回の完全なスキーマセットアップには、次を実行します。

```bash
npm run setup
```

setupコマンドは、互いに独立した暗号学的に安全なランダムなデータベース・JWT・MFAシークレットを含む`.env`を作成し、データベースを初期化してマイグレーションを適用します。アプリケーション用データベースアカウントがまだ存在しない場合は、ブートストラップで正確なホストのアカウントを作成できるよう、先に`MARIADB_ADMIN_URL`を設定してください。共有デモアカウントは作成しません。

## 本番ビルド

TypeScriptソースをコンパイルしてから、生成されたサーバーを実行します。

```bash
npm run build
npm start
```

ブラウザーの自動起動は`npm run dev`専用であり、本番実行では呼び出されません。

本番モードを使用する前に、次を確認してください。

- `HOST`を意図したバインドアドレスに設定します。既定値`127.0.0.1`はループバック専用です。
- 32文字以上の一意な`JWT_SECRET`と`MFA_ENCRYPTION_KEY`を設定します。本番環境では、未設定、プレースホルダー、従来の既定値、または両者が同一の場合は起動を拒否します。
- `WEBAUTHN_RP_ID`と`WEBAUTHN_ORIGIN`を、本番環境のrelying-partyドメインと正確なブラウザーoriginに設定します。
- 公開サインアップを意図していない限り、`REGISTRATION_ENABLED`は未設定または`false`のままにします。
- 認証済みプロジェクトドキュメントを意図的に公開する必要がない限り、`SERVE_INTERNAL_DOCS=false`のままにします。
- `DB_USER_HOSTS`を正確なアプリケーションクライアントホストに設定し、`npm run db:init`を再実行して従来のワイルドカードアカウントを削除します。
- `DATABASE_URL`または`MARIADB_ADMIN_URL`が非ループバックホストを指す場合は`?ssl=true`を追加します。本番環境の起動と`db:init`は平文のリモートデータベース接続を拒否します。
- `PUBLIC_ORIGIN`を正規のHTTPS originに設定します。Posh-ACMEによる直接TLSでは`POSH_ACME_CERT_PATH`とともに`HTTPS_MODE=posh-acme`を使用し、信頼できるリバースプロキシがTLSを終端する場合は`HTTPS_MODE=proxy`を使用します。
- プロキシモードでは、`TRUST_PROXY_ADDRESSES`に正確なプロキシIPまたは可能な限り狭いCIDRを設定します。数値ベースの`TRUST_PROXY_HOPS`信頼は無効化されており、`0`のままにする必要があります。
- プロキシモードではバックエンドHTTPポートを非公開にし、プロキシまたはローカルヘルスチェッカーのみが到達できるようにします。Posh-ACMEモードでは意図したHTTPSリスナーのみを公開します。
- HTTPS、管理されたシークレットストレージ、データベースバックアップ、通常の本番監視を使用します。

直接Posh-ACMEモードでは、共同編集トラフィックを同じネイティブHTTPSリスナーで処理します。リバースプロキシの背後では`/api/collaboration/`のWebSocketアップグレードを有効にし、元のorigin、host、protocolヘッダーを保持してください。[共同編集](../../collaboration/2026-07-29/collaboration.ja.md#認証とネットワーク要件)およびリポジトリの[HTTPSデプロイガイド](../../../deploy/README.md)を参照してください。

`DATABASE_URL`にパスワードがない、または既知のデフォルトパスワードが含まれる場合、サーバーは起動を拒否します。本番環境では、どちらかの暗号学的シークレットが未設定または公開プレースホルダーとして既知の値である場合も拒否します。暗号学的シークレットを設定していない開発環境ではプロセスごとの一時値を使用し、`npm run env:init`は永続的なランダム値を書き込みます。詳細は[セキュリティ](../../security/2026-07-30/security.ja.md)と[設定](../../configuration/2026-07-28/configuration.ja.md)を参照してください。
